AIDE User Manual

Archive · Identify · Determine · Export. See what is in a project, choose what matters, and export it in a form you control.

What AIDE is

AIDE is a local desktop tool. It scans one or more project folders, shows them as a folder tree with a checkbox on every file and folder, and builds a portable package from the files you keep ticked. The package can be documentation, a snapshot to compare against later, or material for another tool, including an AI chat.

Local and safe by designAIDE needs no internet connection and no AI service. It never deletes, moves or overwrites your original files. Everything it writes goes to a folder you choose.

Quick start

  1. Choose Source Folder. Pick the project folder. Repeat to add more folders.
  2. Scan (Ctrl+S). AIDE reads the whole tree, including every subfolder.
  3. Review the tree. Untick what should stay out. Sensitive files start unticked.
  4. Choose Export Folder and pick a format in the dropdown at the top right.
  5. Preview (Ctrl+P) shows exactly what will be included. You can still change ticks from there.
  6. Build Package (Ctrl+B). If a file already exists, AIDE asks what to do: overwrite, create a new version, or skip.
  7. Open the export folder. A JSON manifest describing the scan is also kept in AIDE Box/scan/.

The interface

The numbers on the screenshot match the cards below it.

Main controls

Status lamp and text, the export-format dropdown, Scan, Cancel (stops a running scan) and Build Package.

Scan and selection control

Choose or remove source folders, choose the export folder, Preview, Clear, select or deselect all, select or deselect a whole category, and the Show Binary Files switch.

Source folders and filter

The folders you added, plus a filter that searches file name, path and category.

File tree

Every folder and file with size, category and status. This is where you decide what goes into the package.

Settings

Ignore rules, sensitive patterns, defaults, language and shortcuts. See Settings.

Register for GameBridge

One-time setup that lets GameBridge find this AIDE. See Plugins & GameBridge.

Status

Export folder, files found, included, excluded, sensitive files (red when above zero), current operation and a progress bar.

Log

A timestamped record of what AIDE does: scans, warnings, files it could not read, exports.

Lock Selection

Freezes your ticks and blocks new scans, so a stray click cannot change the result.

Status line and version

The latest message from AIDE and the installed version.

Clear only empties AIDE's source list and file list. Nothing on disk is touched.

File tree and selection

Click a file to tick or untick it. Click a folder to change its whole subtree in one go. A folder shows one of three states:

SymbolMeaning
☑Everything inside is ticked
☐Nothing inside is ticked
◪Mixed: some ticked, some not

Categories

Files are classified as Code, Text, Config/Data, Web, Document, Image, Binary or Unknown. Pick a category in the dropdown, then use Select Category or Deselect Category.

Filter

Typing router in the filter shows router.py, router_core.py and so on. The filter changes what you see, not what is ticked.

Ignored folders and hidden files

Folders like .git, __pycache__, node_modules, venv, build and dist are skipped by default. Hidden files are not listed unless you turn them on in Settings. You can edit the ignore rules there.

Sensitive files

AIDE marks files that look like secrets with ⚠ and the status Sensitive: .env, credentials.json, secrets.json, *.pem, *.key, and names containing password or secret. Even a hidden .env is found and flagged.

Unticked by default, alwaysAIDE never assumes a sensitive file should be exported. If you tick one anyway, the preview warns you before you build.

Exports also never contain the full path of your source folder, only its name, so user names and local folder structure do not leak into packages you share.

Export formats

FormatWhat you get
markdownOne .md file: a file tree, then every ticked file in a code block.
textThe same package as plain .txt.
treeOnly the folder structure of the ticked files. No file contents.
jsonMetadata only: paths, sizes, categories, sensitivity.
Plugin formatsAdded by plugins, for example gbp and exe. See below.

A JSON manifest is always written alongside the main export. Packages land in a subfolder of AIDE Box named after the format. Binary files, images and documents such as PDF and DOCX appear in the list, but their contents are not included.

Settings

  • Ignored directories and file names, and sensitive file patterns (comma-separated).
  • Default export format and default target folder.
  • Show binary files, show hidden files, and whether non-sensitive files are ticked automatically after a scan.
  • Language: leave it empty to follow your system language, or choose one.
  • Keyboard shortcuts: Ctrl+S scan, Ctrl+B build package, Ctrl+P preview. You can rebind them.

Settings are saved locally in your user profile and loaded at the next start.

Plugins and GameBridge

Plugins live in the plugins/ folder next to AIDE, one subfolder per plugin. A plugin is either a main_plugin.py or a packaged .gbp file. AIDE finds them at start-up; a broken plugin is logged and skipped without affecting AIDE. Plugins can add export formats, but they can never delete files or tick boxes for you. See docs/PLUGIN_GUIDE.md to write your own.

Register for GameBridge

If you use GameBridge, press Register for GameBridge once. AIDE writes AIDE Box/reports/plugin_registration.json, which tells GameBridge where AIDE is installed and where its scans live. It only points to the AIDE Box/scan/ folder, so you do not need to register again for each new project. Nothing is written until you press the button.

Building an .exe with the EXE Builder plugin

The exe format turns a Python project into a Windows program.

  1. Scan the project and untick what should stay outside, such as config/ or assets/.
  2. Choose the format exe and press Build Package.
  3. Wait. The first build downloads packages and can take a few minutes. Progress appears in the log.
  4. Copy the result from AIDE Box/exe/ and place your unticked folders next to it.
  • You need a regular Python 3.8 or newer on the computer. The plugin builds in a temporary environment and leaves your Python untouched.
  • Dependencies come from a ticked requirements.txt. Without one, the plugin detects them automatically and saves the list as <project>.requirements.txt so you can edit it.
  • The result is a single .exe with its libraries built in. GUI programs get no console window.
  • Options live in <project>.build_config.json in the export folder, for example "onefile": false or "windowed": false while debugging.
  • Sensitive files are never copied into a build.
AntivirusSingle-file programs are sometimes flagged by antivirus software even when they are harmless. That is a known side effect of how they unpack themselves.

Troubleshooting

ProblemWhat to do
Dialog says the selection is lockedSwitch off Lock Selection before scanning again.
Dialog says no export folderPress Choose Export Folder before building.
A file you expect is missingCheck the ignore rules in Settings, and whether hidden or binary files are shown.
A file could not be readThe log names the file and the reason. The scan carries on with the rest.
EXE build stops at the startThe log lists everything that was missing, for example Python or an entry point such as main.py.
Built program fails with a missing moduleAdd the package to <project>.requirements.txt, or list it under hidden_imports in the build config.
